# AGENTS.md — as5.odesa.ua

> **Спершу прочитай [PROJECT-CONTEXT.md](PROJECT-CONTEXT.md).** Там персональний
> шар пакета v8: профіль, реєстр префіксів сховищ на спільному origin, прийняті
> рішення з датами, свідомі відхилення й перелік того, що тут **не**
> перевіряється автоматично. Цей файл — коротка витримка для щоденної роботи.
>
> Загальні стандарти живуть у `sveltekit-canon/selection_criteria/v8`. Тут — лише
> те, що специфічне для цього репозиторію.

## Що це

Сайт школи в Одесі. Дві мови (`uk` типова, `en`), сім маршрутів,
prerendered повністю. Два з них службові й не в індексі: `/test` (чернетка)
та `/beta-test-checklists` (чеклист для живої людини). Перелік — `HIDDEN_ROUTES`
у `$lib/config/site`; він же знімає з них `canonical` і тримає поза sitemap.

## Архітектура

- **Фреймворк:** SvelteKit 2 + Svelte 5 (**виключно** руни).
- **Профіль:** `static`. Серверного рантайму немає: ні form actions, ні
  `+server.ts`, ні `hooks.server.ts`. Дані — з `+page.ts` і статичного вмісту.
- **Стан:** класи-контролери в `.svelte.ts`. Module-level синглтон — панівна
  форма; `$effect` у його конструкторі кидає `effect_orphan`.
- **Сховище:** фасад `src/lib/services/storage.ts`. Прямий доступ до
  `localStorage` заборонений скрізь, окрім інлайн-скрипта першого кадру в
  `app.html` (він виконується до будь-якого модуля).
- **i18n:** `svelte-i18n`, словники — JSON у `src/lib/i18n/locales/`. Паритет
  ключів тримає інваріант `translations.test.ts`, бо тип їх не звіряє.
- **Публічна адреса:** єдине джерело — `src/lib/config/site.ts`. Ніде більше
  origin не збирається вручну.

## Локальні пастки

| Пастка | Що саме |
|---|---|
| `url.pathname` **уже містить** базу | додавання її вдруге дає canonical у нікуди — так було на кожній сторінці сайту, поки база дорівнювала `/as5.odesa.ua`. Формула лишилася правильною й після переїзду: `canonicalUrl()` бере `SITE_ORIGIN`, а не `SITE_ROOT` |
| Порт dev-сервера | 5193 (`as5-dev` у `.claude/launch.json` кореня GitHub) |
| Дві живі адреси, основна — **власний домен** | сайт віддається і з `https://as5.odesa.ua/` (основна, куплений домен), і з `https://alik532ua.github.io/as5.odesa.ua/` (запасна). Canonical, `og:url`, sitemap і `robots.txt` ведуть на основну; запасна лишається робочою, але в індексі не згадується |
| `paths.base` порожня, і це не помилка | база `''`, бо на власному домені сторінки в корені. Не повертай `/as5.odesa.ua`: 2026-08-15 саме через неї зібраний CSS просив шрифт за `as5.odesa.ua/as5.odesa.ua/fonts/…` — 404, і сайт показувався системними шрифтами. У коді цього не видно ніяк, лише в `build/` або в мережевій панелі |
| `base` і `resolve()` під час prerender — **відносні** | `paths.relative` у SvelteKit типово `true`, тож у `build/` виходить `href="./about"`, а не `/about`. Тому НІКОЛИ не виводь із рядка адреси ні локатор, ні стан: `data-testid="nav-{item.href.replace('/','')}-link"` давав `nav-.about-link`, а `page.url.pathname === item.href` не збігалося ніколи, тобто активний пункт меню не підсвічувався в жодній зібраній сторінці. Ключ для локатора — власне поле, активність — `page.route.id` (`$lib/config/nav.ts`) |
| Шляхи в CSS — теж відносні | CSS не бачить `paths.base`, тож абсолютний шлях прив'язує стилі до однієї адреси. `global.css` тепер тримає `url('../../../static/fonts/…')`, і Vite сам переписує їх на хешовані ресурси. Абсолютний шлях від кореня тут — регрес |
| CSP | доставляється `<meta>`, бо GitHub Pages не дає ставити заголовки. У dev CSP приходить заголовком — поведінка різна (SECURITY-v8 § 6.4) |
| Інлайн-скрипт в `app.html` стоїть **після** `%sveltekit.head%` | мета-політика діє лише на те, що йде після неї. Піднімеш вище — CSP перестане його покривати, а хеш стане декоративним. Хеш рахується з файлу під час збірки (`svelte.config.js`), тож правити сам скрипт безпечно; `check:build` стежить за обома умовами |
| У `<head>`-скрипті немає `document.body` | тіло ще не розібране, звернення кидає `TypeError`. Саме так блок `page-home` не працював жодного разу, і симптому не було: виняток ковтав власний `try/catch` |

## НЕ РОБИ

| Заборонено | Замість цього |
|---|---|
| `writable()`, `readable()`, `derived()` зі `svelte/store` | `$state` / `$derived` у класі-контролері |
| `import { page } from '$app/stores'` | `$app/state` |
| `localStorage.getItem(...)` напряму | `storage` із `$lib/services/storage` |
| `localStorage.clear()` | вибіркове видалення за префіксом — origin спільний із шістьма сусідніми проєктами |
| `{@html}` над чим завгодно | лише над власними даними, з `eslint-disable-next-line` і причиною поруч |
| `${base}/шлях` для посилань | `resolve('/шлях')` з `$app/paths` — типізований проти реальних маршрутів |
| `${base}/images/x.svg` для файлів | `asset('/images/x.svg')` |
| `toLocaleString()` без аргументу | явна локаль: без неї береться локаль **системи**, а не мова сайту |
| `any` | конкретний тип, `unknown` або дженерик |
| `as SomeType` над зовнішнім значенням | type guard: `as` нічого не звіряє |
| `console.log` у коді, що їде в браузер | `console.warn`/`console.error` там, де є що сказати; у `scripts/` правило не діє |
| Компонент чи модуль у `src/lib`, який ніхто не імпортує | підключити або видалити — `src/structure.test.ts` падає на сироті й на ланцюжку сиріт |
| `<svelte:boundary>` без сніпета `failed` | межа знищує власне тіло й рендерить на його місце `failed`. Без нього на екрані **порожньо** |
| `svelte-ignore` без перевірки, що саме він глушить | коментар діє на наступний елемент **і на все його піддерево**. Два рядки, написані про тло модалки, накривали сімнадцять недоступних клавіш піаніно. Перевіряй так: прибери коментарі й прожени `svelte.compile` на файлі |
| Вміст сторінки за клієнтським прапорцем (`onMount`, `IntersectionObserver`) | під час prerender його не буває, тож у `build/` замість блоку лишається заглушка. Так шість відділів школи не потрапляли в HTML головної. Якорі обовʼязкових блоків — у `REQUIRED_CONTENT` (`scripts/check-build.mjs`) |
| Модалка (`aria-modal="true"`) без `use:focusTrap` | браузер обіцянки `aria-modal` не виконує: Tab виходить із діалогу на сторінку під оверлеєм, а після закриття фокус падає на `<body>`. Дія — `$lib/actions/focusTrap` |
| Рядок `<style>` у doc-коментарі всередині `<script>` | svelte2tsx ламається на ньому, і `npm run check` падає з «`<script>` was left open», хоч `svelte/compiler` той самий файл компілює без жодного попередження |

Перші девʼять рядків тримає ESLint, наступні три — `npm test`
(`structure`, `check:build` через `REQUIRED_CONTENT`), останні три — прочитай
уважно: жоден автоматичний гейт їх не ловить, вони тут саме тому.

Вимкнути правило ESLint можна лише разом із записаною поруч причиною
(CODE-QUALITY-v8 § 6.4.1); інваріант `src/eslint-baseline.test.ts` падає, якщо
хтось вимкне його мовчки.

## Конвенції

- **Префікс сховища:** `as5.odesa.ua_`. Єдине джерело — `src/lib/config/storage.ts`.
- **Іменування:** компоненти `PascalCase.svelte`, утиліти `camelCase.ts`,
  контролери з рунами — обов'язково `.svelte.ts`.
- **`data-testid`:** конвенція в TESTID-AND-NAMING-v8; статична перевірка —
  `src/testid-conventions.test.ts`.
- **Тести:** Vitest, файли `*.test.ts` під `src/`. Playwright тут **не стоїть** —
  не пиши файлів під нього (AI-AGENT-PITFALLS-v8 § 1.3). Класи-контролери
  (`.svelte.ts`) тестувати **можна**: у `vitest.config.ts` є плагін `svelte`,
  тож руни в них компілюються. Компонентних тестів усе ще немає — для
  монтування `.svelte` потрібен ще `@testing-library/svelte`, якого тут не
  стоїть.

## Команди перевірки

```
npm run check        # svelte-check, має бути 0 помилок
npm run lint         # eslint, має бути 0 помилок
npm test             # юніт-інваріанти
npm run build        # збірка
npm run check:build  # гейт над build/: canonical, og:image, title, JSON-LD,
                     # robots/sitemap, подвоєна база, позиція й хеш інлайн-скриптів
```

**Результат треба побачити, а не припустити.** Твердження «правило виконано»
робиться після прогону, а не замість нього. Частину дефектів цього проєкту
видно **лише** у `build/` — саме тому `check:build` існує окремо
(AI-AGENT-PITFALLS-v8 § 2).
